# FOMO — Unified Project (Monorepo) Guide

> **Single source of truth for deploying the WHOLE project.**
> Run `bash /app/bootstrap.sh` on a fresh pod and everything comes up:
> backend + admin + public website + MongoDB, all wired to the same backend.

## Components (all under `/app`)

| Component      | Path                  | Stack            | Port | Supervisor program | Exposed via preview URL |
|----------------|-----------------------|------------------|------|--------------------|--------------------------|
| Backend (API)  | `/app/fomo-backend`   | NestJS           | 5000 | `fomo_nest`        | via FastAPI proxy → `/api` |
| FastAPI proxy  | `/app/backend`        | FastAPI/uvicorn  | 8001 | `backend`          | yes (`/api/*` → 5000)    |
| Admin panel    | `/app/frontend`       | React (CRA)      | 3000 | `frontend`         | **yes** — edge router: serves admin at `/admin`, proxies `/` to website |
| Public website | `/app/website_front`  | Next.js 16       | 3001 | `fomo_website`     | via admin proxy at `/` |
| MongoDB        | —                     | mongod           | 27017| `mongodb`          | —                        |

**Routing (preview URL / ingress):** `/api/*` → backend; **everything else → port 3000**.
Port 3000 runs the **admin CRA**, which now acts as the edge router via
`/app/frontend/src/setupProxy.js`:
- `/`  and all non-admin paths → **public website** (Next.js on 3001, reverse-proxied)
- `/admin`, `/admin/*` → **admin panel** (served under `PUBLIC_URL=/admin`)

So on the preview URL: `/` opens the **public website**, `/admin` opens the **admin login**
→ dashboard. This is the intended UX. `/api/*` is handled by the ingress before reaching
port 3000.

## How website ↔ admin are connected
Both the admin and the public website talk to the **same backend** (`fomo-backend`).
The website's API base is set in `/app/website_front/.env.local` (auto-generated by
`bootstrap.sh` from the admin's `REACT_APP_BACKEND_URL`):

```
NEXT_PUBLIC_API_URL=<BACKEND_URL>/api
NEXT_PUBLIC_LOADER_API=<BACKEND_URL>
API_BASE_URL=<BACKEND_URL>
```

So a change made/confirmed in the admin (e.g. flag moderation) is persisted in the shared
DB and shows up on the public site. Backend CORS already allows `localhost:*` and
`*.preview.emergentagent.com` (see `/app/fomo-backend/src/main.ts`).

## Bootstrap (fresh deploy)
```bash
bash /app/bootstrap.sh              # idempotent; installs only what's missing
FORCE_INSTALL=1 bash /app/bootstrap.sh   # force reinstall node_modules
```
The script:
1. Reads `REACT_APP_BACKEND_URL` from `/app/frontend/.env` (portable across deploys).
2. Installs deps + builds backend (`nest build` → `dist/main.js`).
3. Installs admin deps.
4. Clones the website if missing (`FOMOwiki/FOMO-FRONT`, branch **`fomo_v2_architecture`**),
   writes its `.env.local`, patches `package.json` (see gotcha below), installs deps.
5. Installs the `fomo_website` supervisor program from `/app/deploy/fomo_website.conf`.
6. `supervisorctl reread/update` and starts everything.

## Key gotchas (READ before re-installing the website)
- **Branch must be `fomo_v2_architecture`** to match the backend's fomo-v2 endpoints
  (e.g. `/api/fomo-v2/projects/market`, `/api/fomo-v2/flags/...`). `main`/`master` use
  old endpoints that the backend now answers with 404/410.
- **No committed lockfile upstream.** A plain `yarn install` resolves
  `@reown/appkit-adapter-wagmi`'s nested `@wagmi/connectors@8.x` (needs `@wagmi/core@3`)
  against the app's `@wagmi/core@2` → build error `Can't resolve '@wagmi/core/tempo'`.
  Fix (done by bootstrap): pin `resolutions["@wagmi/connectors"]="6.2.0"` in the
  website `package.json`, then `yarn install --ignore-engines`.
- **Node 20 vs engines.** Some web3 deps declare `node>=22`; install the website with
  `--ignore-engines`.
- `supervisord.conf` is **READONLY** — do NOT edit it. The website program lives in a
  separate file: `/app/deploy/fomo_website.conf` (copied to `/etc/supervisor/conf.d/`).
- **Edge routing (website at `/`, admin at `/admin`)** is implemented WITHOUT touching the
  readonly supervisor config:
  - `/app/frontend/package.json` → `"homepage": "/admin"` (admin assets under `/admin/*`).
  - `/app/frontend/src/components/app.tsx` → `<Router basename="/admin">`; the admin routes
    that used to start with `/admin` were normalized (e.g. `/admin/ratings` → `/ratings`,
    `/admin-ai-chat` → `/ai-chat`, `/admin-data-sync` → `/data-sync`,
    `/admin/fomo-v2/*` → `/fomo-v2/*`). Nav links in `static_content/navigation_data.ts`
    updated to match.
  - `/app/frontend/src/setupProxy.js` → reverse-proxies every non-`/admin` path (incl.
    `/_next/*`, websockets) to the website on 3001. Override target with
    `WEBSITE_PROXY_TARGET` env if needed. If the website (3001) is down, `/admin` still
    works; only `/` returns 502 until `fomo_website` is up.

## Flags domain (context for current work)
- Types: `green` (advantages), `yellow` (suspicion), `red` (fraud).
- Public flow: user submits flag on site → status `pending` → admin reviews
  (`/api/admin/fomo-v2/flags`) → `confirm`/`reject`. Confirmed flags become visible.
- Backend: `/app/fomo-backend/src/fomo-v2/domains/flags/` (collection `fomo_v2_entity_flags`).
- Admin UI: `/app/frontend/src/pages/Projects/FomoV2Flags/` + service
  `/app/frontend/src/components/services/fomoV2Flags.ts`.

- **Missing `emoji-mart` dep.** Upstream lists `@emoji-mart/react` + `@emoji-mart/data`
  but NOT its peer `emoji-mart`, so the `/crypto/fomies` page 500s
  (`Module not found: 'emoji-mart'`). bootstrap adds `dependencies["emoji-mart"]="^5"`.
- **Disk is tight.** `/app` is a ~9.8G volume. Next.js dev `.next` cache grows to ~3.5G;
  if installs fail with `ENOSPC`, clear it: `rm -rf /app/website_front/.next` and remove
  any stale `/app/frontend_template_backup`.

## Demo data — Fomies (platform users)
The public **Crypto -> Fomies** tab is the platform's user reputation view.
A "Fomie" == a **User** document with `role:["user"]` + `isCodeActivated:true`.
- Leaderboard: `GET /api/user/fomonauts/all` (+ `/statistics`).
- Profile: `GET /api/persons/:userId?type=fomies` (maps the User via `transformToPerson`).
- Seed script (idempotent, upsert by email): `node /app/fomo-backend/scripts/seed-fomies.js`
  — inserts 2 mock Fomies into `fomo_dev.users`. Also run automatically by bootstrap.
- Manage/delete via the admin **Пользователи** (Users) section.
Rating fields that drive the UI: `activityXP` (0-1000 -> rank name), `verificationStatus`,
`rating`/`fomoScore`, `redFlags`/`greenFlagsList`.
